## Commit message style

Use [Conventional Commits](https://www.conventionalcommits.org/) — short, scannable history for reviewers:


| Prefix      | When                                                   |
| ----------- | ------------------------------------------------------ |
| `feat:`     | New behavior (tier check, crew cap, passenger UI)      |
| `fix:`      | Bug fix                                                |
| `test:`     | Tests only (rare; prefer feat/fix with tests included) |
| `refactor:` | Behavior unchanged, structure improved                 |
| `chore:`    | Tooling, deps, config (Pest, Breeze, Pint)             |
| `docs:`     | README, specs, plans                                   |


**Format:** `feat: add Tier enum with inheritance access rules`

- Imperative mood (`add`, not `added`)
- Lowercase after prefix
- No period at end
- One logical change per commit (see grouped tasks below — not one commit per TDD step)

**Do not** put process notes in commits (e.g. workflow reminders). Those stay in chat only.

### Grouped commits (preferred)

TDD steps (RED → GREEN → REFACTOR) stay inside a task group. **Commit once** when the whole group is green and Pint-clean.

## Code style (PHP / Laravel)


| Standard                | What it is                                             | This project                                                |
| ----------------------- | ------------------------------------------------------ | ----------------------------------------------------------- |
| **PSR-4**               | Autoloading: `App\Models\User` → `app/Models/User.php` | Default via Composer — not “formatting,” just folder layout |
| **PSR-12**              | PHP code layout (indentation, braces, imports)         | Enforced by **Laravel Pint** (already in `composer.json`)   |
| **Laravel conventions** | Structure, naming, Eloquent, Form Requests, Policies   | Primary readability guide                                   |


**Recommendation:** treat **Pint + Laravel conventions** as your industrial baseline. No extra style package required for a strong submission.

**Daily commands:**

```bash
./vendor/bin/pint                    # format changed files
./vendor/bin/pint --test             # CI-style check without writing
php artisan test                     # tests
```

**Optional later (not required for take-home):** PHPStan/Larastan for static types — only if you have time; Pint + tests + clear names matter more to reviewers.

**Readability habits (beyond formatting):**

- Enums for `Role`, `Tier` — avoid magic strings in app code
- Thin controllers; rules in services/policies
- Form Requests for HTTP validation
- Explicit exceptions (`CrewLeadLimitExceeded`, `ResourceAccessDenied`)
- Type hints and return types on all new methods

<?php

namespace App\Enums;

enum Tier: string
{
    case Silver = 'silver';
    case Gold = 'gold';
    case Platinum = 'platinum';

    public function rank(): int
    {
        return match ($this) {
            self::Silver => 1,
            self::Gold => 2,
            self::Platinum => 3,
        };
    }

    public function canAccess(self $required): bool
    {
        return $this->rank() >= $required->rank();
    }
}

<?php

namespace App\Services;

use App\Enums\Role;
use App\Exceptions\CrewLeadLimitExceeded;
use App\Models\User;

class CrewLeadService
{
    private const MAX_CREW_LEADS = 3;

    public function assignCrewLead(User $user): void
    {
        if (User::query()->where('role', Role::CrewLead)->count() >= self::MAX_CREW_LEADS) {
            throw new CrewLeadLimitExceeded('Maximum of 3 crew leads allowed.');
        }

        $user->update(['role' => Role::CrewLead, 'tier' => null]);
    }
}
```

<?php

namespace App\Services\Access;

use App\Exceptions\ResourceAccessDenied;
use App\Models\Resource;
use App\Models\User;

class ResourceAccessService
{
    public function ensureCanUse(User $passenger, Resource $resource): void
    {
        if (! $passenger->isPassenger() || $passenger->tier === null) {
            throw new ResourceAccessDenied('Only passengers with a tier may use resources.');
        }

        if (! $resource->is_active) {
            throw new ResourceAccessDenied('Resource is not available.');
        }

        if (! $passenger->tier->canAccess($resource->minimum_tier)) {
            throw new ResourceAccessDenied('Membership tier does not allow this resource.');
        }
    }
}
```
